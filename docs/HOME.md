# Home：可选的本机家庭功能

Home 运行在当前桌面进程内，不需要手机、机器人、QQ、Hub 或后台共享核心。
退出 Spica 就会停止感知与叫醒执行；仅最小化或收起为桌宠不会停止。
Home 默认关闭。先让普通文字聊天可用，再配置这一页。

## 1. 能做什么，需要什么

| 功能 | 必需条件 |
| --- | --- |
| 桌前有人自动亮屏 | NVIDIA GPU、支持的相机、人体模型、桌区标定；人体存在或新开门事件启动观察；绑定目标显示器 |
| 闹钟、角色叫醒、离床结束语 | 启用 Home 叫醒、可用角色声线和音箱；房间相机及床区用于判断离床 |
| 语音开关灯、晚安关灯 | Zigbee2MQTT / MQTT、两只已安装好的 `TS0001_fingerbot` |
| 回来开灯、欢迎、离开关灯与告别 | 新鲜的人体存在／门磁／照度数据，相机观察，房间场景规则 |
| 晚安休眠、闹钟前恢复 | 先验证主机保持运行时的闹钟；再验证本机 Linux deep/RTC 或 Windows S3/唤醒定时器 |
| 设备灯效 | 仅已实现的具体硬件适配，独立可选；不是通用 RGB 支持 |

没有灯控、传感器或相机时，不要把设置完成当作整条叫醒链已经验收。
Home 状态页会显示实际的未配置、过期、离线和未确认结果；硬件问题不影响普通聊天。
**不包含 H4 机器人功能，也不提供身份认证或家庭安防保证。**

## 2. 安装 Home 运行依赖和人体模型

在桌面应用 Python 环境执行：

```bash
python -m pip install -r docs/requirements/requirements-home.txt
```

这个清单只安装 Python 依赖，不下载模型，不设置设备权限，不启用 Home。
Home 的人体检测使用专门检测人的 YOLO26-L；区域判断不要求正脸。OSNet 用于外观特征；
YuNet/SFace 仅在需要可选人脸登记时准备。默认区域流程不要求登记人脸。
当前推理路径是 **TensorRT + NVIDIA GPU**，没有静默退回 CPU 的方案。

模型导出放在**另一个 Python 3.11 环境**，避免升级 GPT-SoVITS 的依赖：

```bash
python -m venv .venv-home-export
```

Linux 后续使用 `.venv-home-export/bin/python`；Windows 使用
`.venv-home-export/Scripts/python.exe`。先为这个导出环境安装与本机驱动兼容的
CUDA PyTorch，再用它执行：

```bash
python -m pip install -r docs/requirements/requirements-home-export.txt
python scripts/setup_home_models.py
```

上面两行的 `python` 指**导出环境**的 Python。脚本会联网获取校验固定摘要的公开模型，
写入 `home.model_directory`（默认 `models/home`），导出 ONNX 并为当前 GPU 编译 TensorRT。
如需可选人脸功能，加 `--with-faces`。更改相机分辨率后，人脸引擎也须重新准备。
导出和运行环境须使用兼容的 TensorRT/CUDA；GPU、驱动或 TensorRT 改变后可能需要重新编译，
不要跨电脑直接复用旧 `.engine`。

脚本不会打开相机。模型与训练权重许可不同于本项目代码；源地址、摘要和导出版本列在
[准备脚本](../scripts/setup_home_models.py) 中，发布模型前请保留对应上游说明。

## 3. 在设置中填写设备

打开 **设置 → 应用设置 → Home**。先不勾选“启用 Home”。

1. 填 MQTT 地址、端口和主题前缀；常见同机地址为 `127.0.0.1:1883`、主题 `zigbee2mqtt`。
2. 填 Zigbee2MQTT 中人体存在和卧室门磁的 `friendly_name`，不是设备中文描述。
3. 点“刷新设备”，选择相机。Linux 优先 `/dev/v4l/by-id/...`；Windows 选择枚举出的稳定身份。
   不确定时先用“预览相机”，不会保存画面。
4. 填相机实际支持的分辨率和帧率。保存设置，再点“设置桌区／床区”。
5. 在画面中分别拖框，覆盖平时坐姿／躺姿的人体定位圆点；两区尽量不重叠。
   保存区域后关闭窗口。相机或分辨率改变时重新校准。
6. 选择 Home 音箱。“使用日常输出”沿用聊天音箱；“系统默认输出”明确跟随系统。
   备用音箱只在你显式选择后使用。固定设备断开不会偷偷改到其他音箱。
7. 最后启用 Home、保存并重启 Spica。在 **Home 状态** 页检查新鲜观察和可执行状态。

Home 正在用相机时，预览通过同一相机所有者临时交接；叫醒／晚安关键流程可能拒绝校准，
不会为了预览启动第二个抢占相机的进程。

## 4. Zigbee2MQTT 的必要配置

MQTT 适配器当前不支持用户名／密码或 TLS；请使用受控本机连接。它不会自动安装或管理网关。
Zigbee2MQTT 必须发布 `bridge/info`、`bridge/devices`、设备在线状态，以及真实 `last_seen`。
在 Zigbee2MQTT 的配置中为设备开启新鲜度字段，例如：

```yaml
advanced:
  last_seen: ISO_8601
# 合并到你原有的 devices，保留实际 IEEE 地址和其他设备设置。
devices:
  '0x替换为人体存在设备的16位地址':
    friendly_name: room_presence
    filtered_cache:
      - '^presence$'
      - '^illuminance$'
  '0x替换为门磁的16位地址':
    friendly_name: door_entry
    filtered_cache:
      - '^contact$'
```

当前解析字段为 `presence`、`illuminance`、`contact`；不是任意型号传感器都兼容。
缓存过滤用于避免把一次照度上报捎带的旧“有人”当成新事实。保留消息不会续期；
重连／恢复后先建立新鲜上报，再决定动作。

门磁自动场景使用真实开门通知。将
[zigbee2mqtt_home_contact.mjs](../scripts/zigbee2mqtt_home_contact.mjs)
按所用 Zigbee2MQTT 版本的 external extension 方式安装到网关。
当前扩展针对 **SNZB-04P**，发布非 retain 的 `<门磁名>/home/contact`。
其他门磁需要对应适配，不能靠更改型号字符串声称已经支持。

雷达距离、无人延时须按实际房间校准。距离过大可能看到走廊；“连续无人”是有效观察，
不能用离线或消息过期替代。传感器距离不是程序轮询周期。

## 5. 灯和显示器

房间灯使用两只 `TS0001_fingerbot`，分别填写开灯、关灯的 IEEE 地址。
两只都按已支持设备协议做固定全行程按压后回顶，操作前检查状态、必要时先复位。
一只负责开、一只负责关；不支持把同一地址当成两只，也不能在 UI 任意调整危险行程。
填照度阈值后才启用“偏暗自动开灯”，阈值留空不会自动猜测。

- **Linux**：从实际 X11 会话确认 `DISPLAY`、`Xauthority`，用 `xrandr --props` 核对
  输出接口和 EDID 名称后填写。当前按单活动显示器设计，Wayland 不保证自动亮灭。
- **Windows**：填写实际显示器身份（可选绑定字段），底层按 Windows 能力检查控制。
  有多活动显示器或身份不匹配时应先看状态页，不把“已请求”当作物理亮屏回执。

设备灯效默认全部关闭。若手动启用 `home.lights.bedtime_*_leds_off`，只支持适配器中列明的
SL-Infinity、索泰 RTX 4090、指定 ASUS 主板和 ENE 内存路径。Linux 需要匹配的 OpenRGB／设备权限；
Windows RAM 需要保护目录和固定提权任务。相关 `scripts/windows/*rgb*` / `*ram*` 是高级辅助程序，
不是新电脑的一键通用灯控；不要仅为运行桌宠安装它们。辅助失败不能取消闹钟或主灯恢复。

## 6. 闹钟和晚安

先勾选“启用闹钟与叫醒”。窗口顶部闹钟按钮、桌宠右键“闹钟”和 Home 状态页进入同一列表：

- 一个固定作息，可选择星期；工作日指周一到周五，不自动识别节假日。
- 本次调整、跳过和恢复不会永久改固定作息。
- 临时闹钟独立保留。语音限未来 24 小时的单次安排；永久重复通过 UI 设置。
- 角色叫醒逐步变响，默认 3 分钟达到上限、最多 10 分钟；每句后留随机 3–8 秒接话。
  起始／最大音量可配置。看不清时继续，但可靠确认床区无人且床外有人持续 3 秒、至少 6 新帧后结束。
  日常“再睡会儿”等互动不自动延时。明确点击“停止”会停止当前整轮，保留未来安排。
- 结束语按本轮角色生成并等待实际播放条件，不把生成成功当作已经听到。
- 关闭“日常对话语音”仍保留闹钟语音；关闭总“语音引擎”则也关闭角色合成。
  麦克风是否开启由独立偏好决定，不会因闹钟越过完全禁麦。

晚安先完成准备并等待真实回复呈现与资源释放，再执行允许的电源动作。
**先保持 `home.wake.power_control_enabled: false`**，短闹钟验证灯、声音、接话、离床和结束语。
这时不会请求主机挂起。之后才配置 Linux deep/RTC 或 Windows S3：

- Linux 的 `/sys/power/mem_sleep` 必须显示 `[deep]`，当前用户须有非交互 logind 挂起权限和
  `/sys/class/rtc/rtc0/wakealarm` 的受限写权限。不要开放给所有用户；按本机系统策略配置。
- Windows 必须支持 S3，并启用普通唤醒定时器；不自动退回其他睡眠模式。
  唤醒计划由当前用户的固定任务创建，动作只唤醒系统，保留的桌面进程继续运行。
- 闹钟前 5 分钟恢复主机以准备模型，到点再开灯并叫醒。
  `suspend_margin_seconds` 要按本机恢复准备时间校准；留空或时间不足时保持运行。
- RTC／任务读回失败、已有他人电源安排、恢复不明或设备异常，按回执保守处理，
  不会把“系统接受请求”说成“睡眠和恢复验收通过”。
- USB 网关从睡眠恢复后的重连由网关服务自身负责；本项目不附作者机器的 Docker 重启 hook。
  若网关不能恢复，先修好该设备／服务，再依赖自动开灯。

## 7. 当前房间规则与现场验证

日常：新开门或存在触发相机，连续桌区有人才亮屏。任何人都可以，不要求本人脸部。
连续有效无人 5 分钟可关灯；开门且偏暗先亮灯。手动关灯意图会影响后续自动场景。
欢迎要求此前连续无人至少 30 分钟、新开门，以及传感器或相机至少一方确认有人。
告别目前沿用工作日 08:35–09:00：先看见床外有人，再连续新画面 3 秒无人；每天最多一次，
忙时跳过。本版没有 QQ 补发。去洗漱也可能满足这一规则，应在自己房间校准。
这些默认时间策略沿用现有 H1–H3，尚未提供任意场景编辑器。

实际验收至少覆盖：床上不误亮、回桌亮屏；到点开灯/出声；离床停止及结束语；
主动停止整轮；欢迎/告别；最后再做可恢复的休眠/RTC 对照。代码测试不能代替真人与硬件结果。
